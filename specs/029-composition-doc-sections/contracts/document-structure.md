# Contract: Feature Document Structure (`ai/featureDocSections.ts`)

The pure core. Owns the nine-section canon, normalization, validation markers, AI-attribution stripping, and risk-key extraction. No I/O, deterministic → fully unit-tested.

## Canon

```
SECTION_LABELS = [
  'Description', 'Benefit Hypothesis', 'Acceptance Criteria', 'Assumptions',
  'Dependencies', 'In Scope', 'Out of Scope', 'Risks', 'Non-Functional Requirements (NFR)'
]
VALIDATION_MARKER = {
  business:  '⚠ REQUIRES BUSINESS VALIDATION',
  technical: '⚠ REQUIRES TECHNICAL VALIDATION',
  both:      '⚠ REQUIRES BUSINESS & TECHNICAL VALIDATION',
}
```

## `normalizeFeatureDescription(rawDescription): string`

- Parses `rawDescription` into sections by matching each canonical label as a heading (label followed by `:` at a line start, case-insensitive, tolerant of surrounding markup).
- Re-emits **all nine** sections in canonical order, each as `` `<Label>:` `` on its own line followed by that section's content.
- Any label absent from the input is inserted as a **placeholder** (`buildValidationPlaceholder(label)`).
- Content the model wrote — including any `⚠` marker it already added — is preserved verbatim under its label.
- **Idempotent**: `normalize(normalize(x)) === normalize(x)`.

### Guarantees
- Output always contains the nine labels, once each, in order (FR-001, FR-004).
- No section is left blank — a missing one becomes a flagged placeholder (Edge Cases).

## `buildValidationPlaceholder(label): string`

Returns the marker for `DEFAULT_VALIDATION_KIND[label]` on its own line, plus a single neutral line stating the material did not provide enough information — **never** implying AI authorship (FR-022).

## `stripAiAttribution(text): string`

- Removes phrases/sentences attributing authorship to AI (e.g. `generated by AI`, `drafted by an AI`, `as an AI language model`, `AI-composed`, `this was written by AI`), case-insensitive.
- Leaves every other character intact — in particular it MUST NOT touch a `⚠ REQUIRES … VALIDATION` marker (those are about missing info, not AI).

## `extractRiskLinkKeys(description): string[]`

- Returns the distinct Jira issue keys (`/[A-Z][A-Z0-9]+-\d+/`) found **only within the Risks section** of a normalized description, in first-seen order.
- A key appearing in another section (e.g. Dependencies) is not returned.

## Test obligations (TDD, vitest)

- Normalize a description missing several sections → all nine present, in order, missing ones flagged with the correct marker.
- Normalize a well-formed nine-section input → unchanged content, order preserved; idempotent on a second pass.
- `stripAiAttribution` removes AI-authorship phrasing but leaves a `⚠` marker and normal prose intact.
- `extractRiskLinkKeys` returns only Risks-section keys, de-duplicated; ignores keys in other sections.
- `buildValidationPlaceholder` emits the right marker per label and no AI attribution.
